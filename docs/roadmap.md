# 단계별 구현 계획

목표는 저장한 콘텐츠를 정리하고 장소·시기에 맞춰 다시 발견하는 것이다. 하나의 실제 사용자 흐름씩 구현·확인하며 확장한다. 현재 기본 저장함과 로컬 웹 API 연동 코드가 있고 공개 YouTube 제목·Instagram tokenless oEmbed와 실제 키를 사용한 공개 재생목록 17개 조회·웹 후보 선택을 확인했다. 사용자 요청에 따라 NAVER API 검색·발급은 보류하고 공개 재생목록·공유 링크·파일 정리부터 진행한다. Google 프로젝트 생성·YouTube API 활성화는 완료했으며 OAuth client·실제 계정 가져오기는 후속 단계다. 최신 범위는 [API 설정](api-setup.md), 구현은 [Codex 시작점](codex-handoff.md)을 따른다.

2026-10-08 제품명을 핀맵으로 바꾸고 기존 저장소·저장 키·사용자 데이터를 유지했다. 현재 codex/anyjev-instagram-analysis는 codex/content-integrations의03d73fd에서 시작한 후속 브랜치다. Instagram 분석 비용을 줄이기 위한 수동 텍스트 입력·전처리·두 선택형 AnyJev 결정의 UI와 서버 경로를 구현했다. Node 테스트 117개·Python 테스트 22개가 통과했지만 실제 모델 서버·추론·한국어 품질·비용 절감 검증은 없다. 새 PR은 이 문서 갱신 시 아직 생성하지 않았다. [분석 범위와 계약](instagram-analysis.md), [선택 사항인 모델 실행 서비스](../services/anyjev/README.md)를 따른다.

## 바로 이어갈 작업

기본 제품은 React DOM + Vite 웹앱으로 전환했다. 데스크톱/모바일 브라우저를 우선하며 Expo 소스는 이후 네이티브 구현용으로 보관한다. 활성 웹 경로·검사·배포 한계는 [웹앱 시작점](web-app.md), 실제 검증은 [검증 기록](verification.md)을 따른다. 계정 OAuth·운영 배포·근처 알림은 이 전환만으로 완료되지 않는다.

AnyJev 후속 검증은 모델 환경을 확보할 때 진행한다. 현재 PC는 여유 RAM이 부족하여 SDK·가중치를 설치하거나 실행하지 않았으며 미구성 상태에서도 기존 저장함은 사용할 수 있다. 새 기능을 위해 NAVER 발급·Google 로그인·새 OpenAI 키를 요구하지 않는다.

| 순서 | 작업 | 완료를 판단하는 기준 |
| --- | --- | --- |
| 0 | AnyJev 실제 연결·분류 평가 | 충분한 메모리가 있는 별도 환경에서 SDK 0.3.0·Tacit-1.7B와 adaptive=False 확인. 공식 p/reel 링크에 사용자가 제공한 한국어 텍스트만 사용. 분류·근거 부족·생략 손실·타임아웃·캐시·동시 요청·nullable 토큰 기록과 기존 데이터 미변경을 확인하고 같은 baseline의 실제 토큰·지연·비용과 비교 |

Instagram 일반 소비자 저장함과 NAVER 지도 개인 저장 목록의 공개 읽기 API는 제공하지 않는다. YouTube ‘나중에 볼 동영상’도 공식 조회 제한이 있다. 사용자 공유·파일 후보와 직접 만든 재생목록을 유지하며 한 플랫폼의 제한이 기본 저장함 사용을 막지 않게 한다. 좋아요 영상 가져오기는 별도 API를 사용하는 후속 작업이다.

NAVER API HUB 발급·서비스 신청·결제수단 등록·실제 검색은 보류했다. 기존 서버 어댑터와 검색 UI 코드는 보존하지만 현재 앱 진입점에서 검색을 실행하지 않는다. 다시 연동하라는 사용자 요청이 있을 때만 [설정·정책 기록](api-setup.md#네이버-연동-보류)을 확인한다.

## 유지할 구현 경계

- URL 중복과 장소 동일성은 별도 문제다. 확인한 지점이 아닌 링크를 임의로 합치지 않는다.
- 사용자 입력·API 제목 캐시·항목 provenance·좌표를 구분한다. API 확인 시각을 수정만으로 늘리지 않는다.
- YouTube API 항목은 현재 30일 뒤 전체 항목과 메모·방문 표시가 정리되는 MVP다. 자동 갱신·사용자 메모의 독립 보존은 UX와 저장 모델을 함께 설계하는 후속 작업이다.
- NAVER 검색은 현재 보류 안내로 대체했다. 보존한 검색 구현은 원문·지도 확인 전용이며 저장·분류 CTA가 없다. 재개 시에도 새 검색·화면 이탈·최대 24시간 메모리 만료를 유지한다. createContent에서 NAVER provenance/place를 거부하고 mixed batch·중복도 검증을 우회하지 못하게 한다.
- 기존 v2 NAVER API 항목의 읽기·방문 toggle·기존 30일 prune를 호환성 때문에 유지한다. 기존 API 항목 수정은 거부하고 사용자 데이터를 앞당겨 삭제하지 않는다. 기존 보관 동작의 약관 준수 완료는 주장하지 않으며 배포 전 별도 처리 방법을 검토한다. 사용자 직접 공유 지도 링크는 API origin·좌표 없이 수동 저장한다.
- 파일은 후보 확인 후 선택 저장한다. OAuth·실제 export·공유 리스트 자동 동기화와 같은 결과로 설명하지 않는다.
- 저장 실패·unknown schema·migration 실패를 빈 저장함이나 준비 완료로 바꾸지 않는다. 기한 정리 실패도 원본을 보존하고 재시도한다.
- 새 설치는 비어 있다. 실제 API와 예시·모의 응답·미검증 장소/날짜를 구분한다.
- 핀맵 표기로 바꾸어도 moa.library.v1과 기존 ID·제목·메모·방문·생성일·기한을 유지한다. 분석 추천은 자동 저장하지 않으며 사용자가 기존 수정 화면에서 분류를 확인한다.
- AnyJev는 사용자가 직접 입력한 캡션·화면 글자·자막 합계 8,000자만 받고 중복/공백 정리와 생략 표시를 포함해 2,400자 이하로 묶는다. 공식 `/p/`·`/reel/` URL은 식별자이며 URL·미디어·oEmbed HTML을 가져와 분석하지 않는다. 영상 분석·OCR·STT 자동 실행은 미구현이다.
- 분류와 근거 충분 여부의 두 선택형 결정만 요청한다. 낮은 점수·근거 부족·생략은 검토 대상이고 높은 점수도 정확도를 보장하지 않는다. 직접 장소명·주소·날짜를 생성하여 확정하지 않는다.
- 모델 주소 미구성은 외부 요청 없는 설정 안내다. 고정 loopback endpoint·요청/응답/시간 제한·단일 고유 분석·동일 요청 병합을 유지한다. 성공 결정만 15분·최대 100개 메모리에 캐시하고 원문·모델 원문·비밀값·trace를 저장하거나 로그에 남기지 않는다.
- `one_forward`만 허용하며 worker의 adaptive를 꺼서 긴 추론을 예방한다. SDK가 반환하지 않은 생성 토큰 수는 null로 유지하고 문자 감소를 전체 token usage나 절감률로 바꾸지 않는다. 브라우저 취소·Node timeout을 모델 연산 취소 보장으로 설명하지 않는다.

## 팀 협업의 다음 단계

UI PR #1은 열린 draft이며 기반 API·웹 브랜치 codex/content-integrations는 UI head에서 시작했다. 새 AnyJev 분기는 해당 브랜치의 03d73fd를 base로 사용한다. 리뷰·검증 후 의존 순서대로 병합하고 필요하면 PR의 base를 최신 main으로 갱신한다. 병합과 배포는 PR 생성과 별도다. 새 PR을 만들 때 실제 URL·base·검사·모의/실제 검증·남은 한계를 기록한다. 기능별 PR에 SCR/CMP와 실제 Figma 반영 범위를 적는다.

연결 계정의 새 [Figma 작업 파일](https://www.figma.com/design/ejriXVtLOBDSwZ336vDKlZ?node-id=4-256)에서 원본 화면과 리뷰 복제본을 함께 관리한다. 59205e5 초안은 [baseline](../design/history/figma-manifest-2026-10-03-baseline.json)으로 보존하며 최신 부분 갱신·실제 node·reaction 수·시각 확인 범위는 [현재 manifest](../design/figma-manifest.json)를 따른다. 자동 픽셀 동기화는 아니다. 다음 기능의 추가 상태와 프로토타입 재생·좁은 폭·큰 글자·실기기 검증을 이어간다. [Figma 기록](figma-sync.md)과 [현재 검증](verification.md)을 함께 확인한다. 기존 파일의 권한 오류와 과거 호출 한도·캡처는 역사 기록으로 보존한다.

2026-10-08 저장함의 핀맵 표기와 웹 Handoff는 갱신했고 새 Instagram 분석 패널의 Figma 화면은 아직 없다. 패널의 입력·미구성·로딩·오류·추천/검토 상태를 실제 디자인으로 전달하고 코드와의 차이를 다음 작업에 기록한다.

리뷰어·팀 초대와 PR 필수 리뷰·검사 통과 규칙은 실제 GitHub 권한으로 설정한다. 로컬 템플릿·CI 파일만으로 원격 규칙이 적용되지 않는다. 최신 검사·실기기 여부는 [검증 기록](verification.md)에 남긴다.
