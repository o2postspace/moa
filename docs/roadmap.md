# 단계별 구현 계획

제품 목표는 여러 곳에 저장한 콘텐츠를 한곳에 정리하고, 장소·시기에 맞춰 다시 발견하게 하는 것이다. 한 단계마다 실제 사용자 흐름을 확인한 뒤 다음 기능을 추가한다.

**현재 범위:** 로컬 기기에서 링크를 저장하고 검색·분류·방문 상태·상세를 관리하는 첫 기능. 인스타그램·유튜브·네이버 지도 계정 연동, 기존 저장함 일괄 가져오기, 지도 SDK, 백그라운드 위치 알림, AI 자동 추출, 서버 동기화는 아직 완료되지 않았다. 예시 데이터의 장소·행사 정보는 데모이며 실제 일정으로 사용하지 않는다. Figma와 GitHub 생성·연결 결과는 [디자인 전달 기준](design-handoff.md)에 기록한다.

| 순서 | 기능 | 다음 단계로 넘어가는 검증 기준 |
| --- | --- | --- |
| 0 | 기존 저장함 가져오기 검증 | 각 플랫폼의 공식 지원·사용자 내보내기·공유 링크를 조사한다. 본인 동의로 제공된 실제 샘플에서 링크·폴더·메모·페이지 나눔·삭제/비공개 항목 처리 여부를 확인하고, 가능한 경로와 제약을 기록한다. 로그인 후 전체 저장함 접근을 전제로 삼지 않는다. |
| 1 | 첫 링크 저장 | 유효한 링크와 제목·분류를 추가하고 저장함·상세에서 확인한다. 검색·분류·방문 상태 변경, 앱 재실행 후 유지, 중복 안내, 잘못된 URL, 저장 실패 후 입력 유지를 검증한다. 외부 플랫폼·AI API 없이 동작한다. |
| 2 | 정리 확장 | 삭제·일괄 수정·보관·폴더를 순차 추가한다. 원본 출처와 사용자 메모가 유지되고 잘못된 정리 작업을 복구할 수 있다. 같은 장소 묶기는 지점과 불확실성을 확인한 후 도입한다. |
| 3 | 통합 지도 | 네이버 저장 장소와 콘텐츠의 장소를 공통 장소 모델로 연결한다. 지도와 목록의 장소 수가 일치하고, 장소 없는 콘텐츠가 사라지지 않는다. 복수 장소·동명이인·다른 지점·좌표 확인·지도 오류·길찾기를 검증한다. |
| 4 | 근처·기간 알림 | 전경에서 위치·기간 조건부터 확인하고 이후 백그라운드 알림을 추가한다. 실제 iOS·Android 기기에서 권한 거절, 제한 권한, 앱 종료, 배터리 제약, 중복 알림, 종료된 행사 제외를 검증한다. 도착 즉시 알림을 보장하지 않는다. |
| 5 | 개인화 비서 | 저장 이유·방문 기록·일정으로 제안을 만든다. 추천 이유와 근거를 보여 주고, 기간·위치 오류를 수정하고, 무시·알림 빈도를 제어할 수 있다. AI 사용 전에 데이터 범위·보존·동의·비용과 품질 평가를 확정한다. |

0번 조사와 1번 구현은 병행할 수 있다. 조사 결과에 따라 가져오기 어댑터를 추가하며, 한 플랫폼의 제한 때문에 로컬 저장함 사용을 막지 않는다.

## 단계마다 지킬 구조

- 콘텐츠 원본, 장소, 행사 기간을 분리한다. 하나의 장소에 여러 원본, 하나의 원본에 여러 장소가 연결될 수 있어야 한다.
- 가져오기 기능은 플랫폼별 어댑터로 만들고 저장·정리 화면은 공통 모델을 사용한다.
- 미확인 장소·날짜는 상태로 기록한다. 확인 전에는 위치·행사 알림 대상에 넣지 않는다.
- 단계별 이슈에 사용자 문제, 범위, SCR/CMP ID, 완료 기준을 적는다. PR 하나는 리뷰 가능한 하나의 흐름을 중심으로 한다.
- 각 병합 전에 typecheck, lint, 의미 있는 동작 검사, 토큰 검사, 웹 빌드를 수행하고 네이티브 확인 여부를 별도로 기록한다.

## 협업 연결 시 할 일

1. UI/UX 팀의 Figma 프로젝트·파일 URL과 편집 권한을 연결하고 [디자인 전달 기준](design-handoff.md)의 페이지·ID를 적용한다.
2. GitHub 원격을 연결하고 UI/UX·개발팀을 초대한다. 실제 팀 계정으로 리뷰어와 담당자를 정한다.
3. GitHub에서 PR 필수 리뷰와 `quality` 검사 통과 규칙을 설정한다. 로컬 `.github/workflows/ci.yml` 작성만으로 원격 규칙이 적용되지는 않는다.
4. 첫 링크 저장 흐름을 함께 리뷰하고 iOS·Android 실제 기기 검증을 남긴다.
