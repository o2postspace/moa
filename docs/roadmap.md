# 단계별 구현 계획

목표는 저장한 콘텐츠를 정리하고 장소·시기에 맞춰 다시 발견하는 것이다. 하나의 실제 사용자 흐름씩 구현·확인하며 확장한다. 현재 기본 저장함과 로컬 웹 API 연동 코드가 있고 공개 YouTube 제목·Instagram tokenless oEmbed의 실제 응답 성공을 확인했다. OAuth·재생목록·NAVER 검색은 자격 증명 설정 후 실제 검증이 남아 있다. [현재 구현과 시작점](codex-handoff.md)

## 바로 이어갈 작업

| 순서 | 작업 | 완료를 판단하는 기준 |
| --- | --- | --- |
| 1 | Google/NAVER 설정과 실제 연동 | 비밀값을 서버 환경 파일에만 설정. Web OAuth·본인 일반/공개 재생목록·선택 저장·2페이지·중복과 NAVER 검색·주소·좌표의 실제 응답 확인 |
| 2 | 연결·가져오기 실패 검증 | 동의 거절·만료·서버 재시작·네트워크·API 제한, 로컬 이동/쓰기 실패, 모든 계정 가져오기 항목 삭제 후 remote revoke 실패·재시도 확인 |
| 3 | 파일 가져오기 호환성 | 동의받고 익명화한 export 샘플로 링크·제목 후보 확인. 제한된 JSON/TXT 외의 규격을 공식 형식으로 단정하지 않음. 개인정보·중첩 메시지를 읽지 않음 |
| 4 | 외부 제목과 사용자 입력 보존 | 수동 제목·URL/장소 변경·30일 기한·해제 후 삭제 확인. API 출처를 잃은 복사본이 생기지 않도록 정책·표시·테스트를 함께 정리 |
| 5 | 디자인·실기기 전달 | 기존 Figma 파일 편집 권한 또는 사용자 지정 새 파일 확보. SCR-001~005/CMP 매핑과 API 화면·오류·설정 전 상태 반영. 실기기 파일 선택·지도 앱·키보드·접근성 검증 |

Instagram 일반 소비자 저장함과 NAVER 지도 개인 저장 목록의 공개 읽기 API는 제공하지 않는다. YouTube ‘나중에 볼 동영상’도 공식 조회 제한이 있다. 사용자 공유·파일 후보와 직접 만든 재생목록을 유지하며 한 플랫폼의 제한이 기본 저장함 사용을 막지 않게 한다. 좋아요 영상 가져오기는 별도 API를 사용하는 후속 작업이다.

| 운영 연동 | HTTPS·사용자별 인증/세션·토큰 보호·네이티브 OAuth·기기 간 데이터 | 사용자 간 격리, 취소/만료 감지·보존·삭제, OAuth 출시 검증. localhost 서버를 그대로 공개하지 않음 |
| 통합 지도 | 콘텐츠·확인한 장소를 공통 장소 모델·지도 SDK로 연결 | 목록/지도 수 일치, 장소 없는 콘텐츠 유지, 복수 장소·다른 지점·미확인 좌표. 원문 열기와 지도 SDK 완료 구분 |
| 행사 기간 | 출처 있는 시작/종료일·시간대·확인 상태 | 공식 일정 확인, 종료/변경/취소·날짜 누락 처리. 사용자 예시를 확정 행사로 만들지 않음 |
| 근처 알림 | 전경 위치·기간 조건부터, 이후 백그라운드 알림 | 실기기 권한 거절·제한·종료·배터리·중복·종료 행사 제외. 도착 즉시 알림을 보장하지 않음 |
| 개인화 비서 | 저장 이유·방문 기록·일정에 근거한 제안 | 근거·수정·무시·빈도 제어, 동의·보존·비용·평가. 외부 데이터를 승인 범위 밖 분석으로 사용하지 않음 |

## 유지할 구현 경계

- URL 중복과 장소 동일성은 별도 문제다. 확인한 지점이 아닌 링크를 임의로 합치지 않는다.
- 사용자 입력·API 제목 캐시·항목 provenance·좌표를 구분한다. API 확인 시각을 수정만으로 늘리지 않는다.
- API 항목은 현재 30일 뒤 전체 항목과 메모·방문 표시가 정리되는 MVP다. 자동 갱신·사용자 메모의 독립 보존은 UX와 저장 모델을 함께 설계하는 후속 작업이다.
- 파일은 후보 확인 후 선택 저장한다. OAuth·실제 export·공유 리스트 자동 동기화와 같은 결과로 설명하지 않는다.
- 저장 실패·unknown schema·migration 실패를 빈 저장함이나 준비 완료로 바꾸지 않는다. 기한 정리 실패도 원본을 보존하고 재시도한다.
- 새 설치는 비어 있다. 실제 API와 예시·모의 응답·미검증 장소/날짜를 구분한다.

## 팀 협업의 다음 단계

UI PR #1은 열린 draft이며 현재 API 브랜치는 UI head에서 시작했다. 리뷰·검증 후 의존 순서대로 병합하고 필요하면 API PR의 base를 최신 main으로 갱신한다. 병합과 배포는 PR 생성과 별도다. 기능별 PR에 quality 검사·실제 검증 기록·SCR/CMP ID·남은 한계를 적는다.

새 Figma 계정 연결은 확인했지만 기존 파일 요청은 편집 권한 부족으로 거부됐다. 과거 호출 한도와 구분하고 [Figma 기록](figma-sync.md)을 따른다. 파일 소유자가 권한을 공유하거나 사용자가 새 파일을 정한 뒤 실제 node·스크린샷으로 갱신을 확인한다. SVG·이전 캡처·코드 매핑만으로 동기화 완료를 표시하지 않는다.

리뷰어·팀 초대와 PR 필수 리뷰·검사 통과 규칙은 실제 GitHub 권한으로 설정한다. 로컬 템플릿·CI 파일만으로 원격 규칙이 적용되지 않는다. 최신 검사·실기기 여부는 [검증 기록](verification.md)에 남긴다.
