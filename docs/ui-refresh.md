# 모아 UI 리디자인 · 디자인/개발 전달

이번 변경은 앱 코드에 반영된 두 번째 UI입니다. 흰 배경, 짧고 진한 제목, 따뜻한 회색 카드, 둥근 필터와 원형 뒤로가기 버튼을 사용하고 모아의 주황색을 유지했습니다. 참고 화면은 [MMM / WWIT](https://wwit.design/2025/03/04/mmm/)입니다.

`design/moa-ui-refresh.svg`는 UI/UX 팀이 Figma에 가져와 작업을 시작할 수 있는 벡터 초안입니다. **기존 Figma 파일에는 이번 리디자인이 아직 반영되지 않았습니다.** Starter MCP 호출 한도로 원격 읽기/편집을 이어갈 수 없어, 현재 앱 코드와 기존 Figma 사이에 차이가 있습니다. SVG 생성은 사용자 계정의 Figma를 편집하는 작업이 아닙니다.

## 전달 파일과 기준

| 파일 | 역할 |
| --- | --- |
| `design/moa-ui-refresh.svg` | 세 화면을 나란히 배치한 벡터 초안. 각 화면 390 × 844, 바깥 캔버스 1234 × 900 |
| `design/tokens.json` | 현재 색·여백·폰트·크기의 기준 |
| `src/theme/tokens.ts` | 앱에서 사용하는 생성 토큰 |
| `design/figma-manifest.json` | 기존 원격 Figma 노드와 검증 기록. 리디자인 반영 여부는 이 문서와 함께 확인 |
| `design/figma-preview.png` | 이전 Figma 화면의 검증 이미지. 이번 리디자인의 이미지가 아님 |

SVG에는 `SCR-001-Library`, `SCR-002-AddLink`, `SCR-003-ContentDetail` 그룹과 코드 경로를 담은 `data-source`가 있습니다. 파일은 `<rect>`, `<path>`, `<circle>`, `<line>`, `<text>`로 구성하며 외부 사진, 래스터 화면, 외부 폰트 파일을 포함하지 않습니다.

## 화면과 동작

| 화면 | SVG 상태 | 앱의 실제 동작과 코드 |
| --- | --- | --- |
| SCR-001 저장함 | 첫 실행, 저장 수 0, 출처 메뉴 닫힘 | `src/app/index.tsx`: 전체 저장/방문 완료 탭, 제목·장소·메모 검색, 분류 필터, 펼쳐지는 출처 필터, 링크 추가 |
| SCR-002 링크 추가 | 링크·제목 공란, 기타 선택, 선택 정보 접힘 | `src/app/add.tsx`: 링크·제목 필수, 분류 선택, 장소·메모 접기/펼치기, 하단 고정 저장. 오류 시 첫 필수 입력으로 이동하고 입력에 초점. 기존 콘텐츠 수정도 같은 폼 사용 |
| SCR-003 콘텐츠 상세 | 상단에 `예시`로 표시한 가상 콘텐츠 | `src/app/content/[id].tsx`: 원본 링크 열기, 방문 완료 토글, 내용 수정. 직접 적은 장소·메모 표시, 하단 고정 동작 |

저장 수는 탭 제목과 8px 간격으로 분리합니다. 목록 제목과 결과 개수도 같은 간격을 사용합니다. 실제 콘텐츠 카드에서는 `CategoryStamp`를 오른쪽에 배치하고 방문 완료 상태는 초록색으로 표시합니다. 기본 행동인 저장/원본 보기에는 주황색 버튼을, 선택 정보와 보조 행동에는 회색 표면을 사용합니다.

SVG는 정적인 기본 상태 3개만 보여 줍니다. 출처 메뉴가 열린 상태, 선택 정보가 펼쳐진 상태, 검색 결과 없음, 방문 완료, 저장 중, 오류 상태는 앱 코드에서 확인하고 라이브 Figma를 갱신할 때 추가합니다. 중복·쓰기 오류와 기존 콘텐츠로 이동하는 링크는 추가 화면의 저장 바 위에, 원본 열기·방문 처리 오류는 상세 화면의 고정 하단 영역에 표시합니다.

네이버 지도 등의 링크는 저장할 수 있습니다. 이미 저장한 목록 자동 가져오기, 지도 연결, 현재 위치·축제 기간 알림은 이번 버전에 구현되어 있지 않습니다. 상세 화면의 장소는 사용자가 적은 값이며 예시에는 확인된 축제 일정이나 운영 정보를 넣지 않았습니다.

## 현재 스타일

| 토큰 | 값 | 적용 |
| --- | --- | --- |
| `color.background`, `color.surface` | `#FFFFFF` | 화면, 고정 하단 영역 |
| `color.surfaceMuted` | `#F5F5F1` | 카드, 입력, 보조 버튼 |
| `color.ink` | `#20231F` | 제목, 본문 |
| `color.secondary` | `#62685F` | 설명, 보조 정보 |
| `color.accent` | `#C94C2B` | 주 행동, 아이콘, 선택 탭 밑줄 |
| `color.accentInk` | `#A83A20` | 연한 주황색 배경 위 작은 글자 |
| `color.accentSoft` | `#FCEBE3` | 선택 칩, 상단 링크 추가 |
| `color.border` | `#E9EBE5` | 구분선, 종이 아이콘 테두리 |
| `color.green`, `color.greenSoft` | `#3A654C`, `#E9F1EA` | 방문 완료 상태 |
| `color.error` | `#A92D25` | 오류 |

폰트는 Noto Sans KR Regular 400 / Medium 500 / Bold 700입니다. 앱에서는 `NotoSansKR_400Regular`, `NotoSansKR_500Medium`, `NotoSansKR_700Bold`를 사용합니다. SVG의 대체 폰트는 Malgun Gothic, sans-serif입니다. 기본 본문 14/23, 설명 12/20, 소제목 16/26, 큰 제목 28/39입니다. 상세 콘텐츠 제목은 25/36, 빈 상태 제목은 20px로 조정합니다.

화면 좌우 여백 24px, 주요 입력/버튼 최소 높이 56px, 칩/아이콘 터치 영역 최소 48px입니다. 여백은 4/8/12/16/24/32/48px, 모서리는 12/20/28px와 pill입니다. `CategoryStamp`는 겹친 두 장의 종이와 분류별 선 아이콘으로 구성합니다. SVG 아이콘은 이 형태를 직접 그린 벡터이며 앱의 Ionicons와 윤곽이 조금 다를 수 있습니다.

## UI/UX 팀: SVG 가져오기

1. [모아 Figma 파일](https://www.figma.com/design/sNrklbLn8Fd9HXMU3GLQUt)을 열고 `02 Design & Handoff` 페이지에서 기존 화면 옆에 `UI Refresh · Draft` 프레임을 만듭니다. Starter의 페이지 수 제한을 고려해 기존 페이지의 별도 영역을 사용합니다.
2. Noto Sans KR을 사용할 수 있는 환경에서 `design/moa-ui-refresh.svg`를 캔버스에 끌어 넣습니다. 각 화면 그룹을 분리해 390 × 844 프레임으로 정리하고 순서를 저장함 → 링크 추가 → 상세로 유지합니다.
3. `<text>` 원문이 SVG에 들어 있으나 Figma 가져오기 방식과 폰트 가용성에 따라 글자가 윤곽선으로 변환되거나 줄바꿈·폭이 달라질 수 있습니다. 텍스트가 윤곽선이면 코드 문구를 사용해 네이티브 텍스트로 다시 작성합니다. 한글 글꼴, 제목 줄바꿈, 버튼 글자, 분류 필터가 겹치지 않는지 확인합니다.
4. 화면 그림을 바탕으로 네이티브 Auto Layout, 텍스트 속성, 변수 연결, 기존 컴포넌트 인스턴스로 구성합니다. SVG 가져오기만으로 컴포넌트 라이브러리, 반응형 레이아웃, 프로토타입 동작 또는 Code Connect가 생기지는 않습니다.
5. 실제 앱의 390px 화면과 비교한 뒤 좁은 화면·긴 제목·키보드·safe area 상태를 별도 확인합니다. SVG는 상태 바와 OS 내비게이션 바를 포함하지 않은 앱 콘텐츠 영역입니다. 세로 스크롤의 기본 위치를 표현하며, 상세 화면의 저장일 등 아래쪽 내용은 스크롤해서 보게 됩니다.

## 라이브 Figma를 갱신할 때 보존할 노드

아래 ID는 이전 구현에서 기록한 값입니다. 이번 리디자인 동안 원격 읽기가 제한되어 현재 파일을 다시 검증하지 못했으므로, 편집 전 실제 파일에서 ID와 노드 종류를 확인합니다.

| 대상 | 기존 ID |
| --- | --- |
| Design & Handoff 페이지 | `2:3` |
| Foundations / Components / Screens / Handoff 섹션 | `3:2` / `3:3` / `3:4` / `3:5` |
| SCR-001 Library / SCR-002 AddLink / SCR-003 ContentDetail | `4:32` / `4:35` / `4:38` |
| CMP-001 ContentCard / CMP-002 FilterChip | `4:18` / `3:63` |
| CMP-003 PrimaryButton / CMP-004 SourceBadge / CMP-005 EmptyState | `3:76` / `3:58` / `4:19` |
| FormField | `3:85` |
| Moa Primitives / Moa Tokens | `VariableCollectionId:2:4` / `VariableCollectionId:2:5` |
| 이전 화면 검증 래퍼 / 컴포넌트 상태 래퍼 | `4:26` / `9:116` |

기존 Figma는 이전 배경색 `#F7F5F0`, 글자색 `#242924`, 보조색 `#60675F`, 테두리 `#E2E5DD`, 모서리 8/16/24px, 주요 컨트롤 52px의 첫 버전입니다. 이번의 `surfaceMuted`, `accentInk`, CategoryStamp, 접힌 출처 필터, 방문 완료 탭, 선택 정보 접기, 고정 하단 버튼 구성이 반영되어 있지 않습니다. 기존 파일의 검증 이미지를 현재 코드와 동기화된 결과로 사용하지 않습니다.

라이브 반영 순서는 다음과 같습니다.

1. 원격 접근이 가능해지면 기존 화면·컴포넌트·변수 컬렉션을 읽고 현재 코드 토큰과 비교합니다. 기존 화면 루트와 메인 컴포넌트, 컬렉션 ID를 유지해 팀 링크와 매핑을 보존합니다.
2. 변수와 텍스트 스타일을 먼저 업데이트합니다. `surfaceMuted`, `accentInk`, `greenSoft`가 없으면 추가하고 현재 역할에 맞게 변수 연결을 확인합니다.
3. 버튼·칩·입력·카드·빈 상태를 갱신하고 CMP-006 CategoryStamp를 새 컴포넌트로 만듭니다. 크기/분류/방문 상태를 표현하며 카드와 빈 상태의 인스턴스 연결을 유지합니다.
4. 기존 화면 `4:32`, `4:35`, `4:38` 내부를 새 구조로 갱신합니다. Auto Layout과 편집 가능한 텍스트를 사용하고 출처 메뉴, 필수 입력 오류, 선택 정보 펼침, 방문 완료 상태를 추가합니다. SVG를 한 장의 이미지로 붙여 기존 화면을 대체하지 않습니다.
5. 구조 읽기로 화면 크기·텍스트·인스턴스·폰트·변수 연결을 확인하고, 전체 화면 이미지와 실제 앱을 비교합니다. 390px 기본 화면, 320px 좁은 화면, 긴 제목, 필터, 수정, 오류, 키보드와 safe area를 확인합니다.
6. 실제 원격 반영과 검증을 마친 뒤 `design/figma-manifest.json`의 상태·노드 매핑·검증 기록을 갱신하고 새 검증 이미지를 저장합니다. 기존 검증 기록은 이전 버전이라는 점을 보존합니다.

## 이번 전달의 검증 범위

SVG의 XML, 세 화면 크기, 고유 ID, 텍스트·벡터 구성과 외부 이미지 미포함을 로컬에서 확인했습니다. Noto Sans KR을 로드한 1282 × 948 브라우저에서 세 화면의 잘림·겹침 없이 렌더링되는 것을 확인했고, `design/ui-refresh-preview.png`에 기록했습니다. 실제 앱은 390 × 844의 저장함·추가·상세 화면과 320 × 800의 긴 제목 상세 화면을 확인했습니다. 검사 상세는 `docs/verification.md`를 참고합니다. Figma 가져오기 결과, 앱과의 픽셀 일치, 네이티브 기기 동작은 아직 검증하지 않았습니다. 실제 Figma 리디자인 완료 여부는 라이브 파일을 수정하고 새 구조·화면 검증을 마친 후에만 기록합니다.
